# /cmp-merge-tests — Vanessa-тесты по результатам обновления

Автор: **WNX** · Версия: 0.1 · Статус: каркас, генератор рабочий

Второй скилл серии cmp-merge: после генерации ПНСО (см. скилл `cmp-merge`) превращает
результат обновления — «что и где изменено, кто победил» — в исполняемые сценарии
**Vanessa Automation** (BDD-фреймворк для 1С, https://github.com/pr-mex/vanessa-automation).

Сценарии рассчитаны на запуск **аналитиком** интерактивно: открыл `VanessaAutomation.epf`
в режиме предприятия, указал каталог фич, нажал «Запустить сценарии». Фичи на русском,
сгруппированы по видам проверок, размечены тегами для выборочного запуска.

## Вход / Выход

| Вход | Откуда | Что даёт |
|------|--------|----------|
| `classification.json` | скилл `cmp-merge` (out/) | классы объектов: vendorOnly, newInT, baseOnly, conflict, deletedInT |
| `merge-settings.xml` | скилл `cmp-merge` (ПНСО) | правила объединения (кто победил), целевая версия |
| Выход | `va_features/` | feature-файлы Vanessa + каркасы пользовательских шагов |

## Использование

```bash
python ${CLAUDE_SKILL_DIR}/scripts/va_generate.py \
    --classification <out>/classification.json \
    --merge-settings merge-settings.xml \
    --out-dir va_features \
    [--target-version <целевая версия, иначе берётся из ПНСО>]
```

## Структура генерируемых фич

| Файл | Тег | Проверка | Механизм VA |
|------|-----|----------|-------------|
| `01_ВерсияОбновления.feature` | @Версия | версия конфигурации = целевой | код встроенного языка |
| `02_Метаданные_Наличие.feature` | @Метаданные | затронутые объекты присутствуют, удалённые отсутствуют | код встроенного языка (`Метаданные.НайтиПоПолномуИмени`) |
| `0n_Формы_<Вид>.feature` | @Формы | smoke-открытие форм затронутых объектов (списки справочников/документов, формы отчётов/обработок) | навигационные ссылки `e1cib/list/...`, `e1cib/app/...` |
| `0n_Report_Формы.feature` | @Отчеты | открытие + кнопка «Сформировать» | шаги TestClient |
| `90_Доработки_Каркасы.feature` | @Доработки | TODO-каркасы проверок собственных доработок | пользовательские шаги (VA генерирует шаблоны epf) |

Объекты без форм (регистры, общие модули, подписки, роли, планы обмена) проверяются
наличием метаданных и компилируемостью через код встроенного языка.

## Ограничения и TODO (до 1.0)

- Шаги-заготовки (кнопки, ожидания) — эскизные: сверить синтаксис с версией VA
  (см. reference/va-steps.md), VA сам помечает незнакомые шаги.
- VAParams.json (консольный запуск, отчёты Allure/JUnit) — не генерируется,
  аналитик запускает интерактивно; добавить при необходимости.
- Проверки проведения документов — сознательно не генерируются автоматически
  (создание данных); закладывать вручную в каркасы.
- Семантика доработок неизвестна генератору — фичи @Доработки требуют наполнения.

## Опыт применения (пример прогона, обезличено)

11 фич: версия, метаданные (~1500 объектов), формы по видам (Catalog/Document/Enum/
ExchangePlan/Task/ChartOfAccounts/DataProcessor/Report — 511 отчётов), каркасы доработок.
