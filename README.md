# 1C CFG Update — скилл cmp-merge (автор: WNX)

> Навык для AI-агентов (Claude Code, ZCode и других платформ со скиллами) — **контролируемое
> обновление модифицированной конфигурации 1С:Предприятие 8.3 с сохранением доработок**.

Скилл решает классическую задачу сопровождения: конфигурация стоит на поддержке и имеет
собственные доработки, вендор выпустил новый релиз, и нужно перенести изменения вендора,
**не затерев при этом свои доработки** — и сделать это управляемо, по файлу настроек
сравнения и объединения (ПНСО), а не вслепую.

## Как это работает

Ядро — трёхстороннее сравнение XML-выгрузок конфигураций:

| Роль | Что это | Откуда |
|------|---------|--------|
| **B** — основная | Конфигурация, которую обновляем (с доработками) | Выгрузка из конфигуратора: `Файл → Выгрузить конфигурацию в файлы` |
| **P** — предок | Чистая версия поставщика, на которой стоит база | Выгрузка из чистого `1Cv8.cf` версии-предка (дистрибутив вендора) |
| **T** — цель | Полная конфигурация целевой версии | Выгрузка из полного `1Cv8.cf` целевого релиза |
| **Эталон** | Файл настроек, сохранённый из диалога платформы для той же пары версий | Конфигуратор: окно сравнения-объединения → «Действия → сохранить настройки» |

Перекрёстное сравнение `P↔B` даёт доработки базы, `P↔T` — изменения вендора. Классификация
объектов (изменено только вендором / только нами / дважды изменённые / новые / удалённые)
и оценка коллизий показывают точный масштаб ручной работы. Генератор собирает ПНСО:
шапку и точечные решения — из эталона, массовые правила — по профилю политики.

## Быстрый старт

```bash
# 1. Классификация объектов (md5-сравнение трёх выгрузок, кэш хэшей)
python .claude/skills/cmp-merge/scripts/cmp_merge.py classify \
    --b <путь к выгрузке базы> --p <путь к чистому предку> \
    --t <путь к целевой выгрузке> --out-dir out

# 2. Коллизии в модулях (.bsl) — трёхстороннее слияние merge3
python .claude/skills/cmp-merge/scripts/cmp_merge.py collisions \
    --b ... --p ... --t ... --out-dir out

# 3. Структурный разбор XML, изменённых обеими сторонами
python .claude/skills/cmp-merge/scripts/cmp_merge.py xml-collisions \
    --b ... --p ... --t ... --out-dir out

# 4. Генерация ПНСО (эталон + профиль политики)
python .claude/skills/cmp-merge/scripts/cmp_merge.py generate \
    --etalon <MergeSettings.xml> --classification out/classification.json \
    --out-file merge-settings.xml \
    --vendor-full "Report.РегламентированныйОтчет" \
    --summarize "Role."
```

Полученный `merge-settings.xml` подгружается в окне сравнения и объединения конфигуратора
при обновлении из CFU (или при объединении из полного CF) — и применяется как готовый
набор правил.

## Профиль политики

Ядро правил слияния универсально для любой конфигурации; под конкретный проект
настраиваются только массовые решения для дважды изменённых объектов:

- `--vendor-full "префиксы"` — области, отдаваемые вендору целиком (типично: регламентированная
  отчётность, обновляемая вендором независимо и не дорабатываемая на проекте);
- `--summarize "префиксы"` — области, объединяемые с приоритетом основной конфигурации
  (типично: права ролей — суммирование);
- точечные решения по свойствам (дважды изменённые реквизиты, составы, движения) —
  в эталонном файле из платформы и переносятся из него автоматически.

## Правила слияния (ядро)

- Минимальная единица слияния — не объект и не файл, а процедура/строка модуля, узел
  свойства метаданных, узел формы.
- Независимые изменения обеих сторон объединяются автоматически.
- Вставки вендора встраиваются, если не затрагивают изменённые нами места.
- Прямая коллизия (обе стороны меняли одно место) — приоритет основной конфигурации,
  вендорская версия фиксируется в отчёте коллизий.
- Метаданные объединяются поэлементно (добавления суммируются), составы типов — объединением
  множеств.
- Обязательная верификация после применения: выгрузка результата и проверка «вендорское
  вошло» (R↔T) и «доработки живы» (R↔B), компиляция изменённых модулей.

Полное описание — в [SKILL.md](.claude/skills/cmp-merge/SKILL.md) (роли каталогов,
правила слияния, референс-прогон).

## Требования

- Python 3.10+, пакет `merge3`.
- Платформа 1С:Предприятие 8.3 — только на этапах выгрузки XML-каталогов (конфигуратор)
  и применения ПНСО; сам скрипт с ней не работает.
- XML-выгрузка должна быть выполнена одной версией платформы внутри каждой роли
  (B, P, T) — смешение версий формата выгрузки даёт ложные различия.
